# System design: Платформа онлайн-обучения

## Введение

Данный документ представляет собой концептуальный системный дизайн для потенциального улучшения существующей платформы онлайн-обучения. В нем рассматривается возможность масштабирования системы до уровня крупной образовательной платформы с миллионной аудиторией.

### Цель документа
- Предложить архитектурные решения для масштабирования системы
- Оценить необходимые ресурсы и инфраструктуру
- Определить потенциальные узкие места и способы их устранения
- Создать дорожную карту развития системы

### Важные замечания
- Все расчеты и оценки являются приблизительными и могут корректироваться в зависимости от реальных потребностей
- Предложенная архитектура может быть реализована постепенно, по мере роста системы
- Документ служит отправной точкой для обсуждения и планирования, а не финальным техническим заданием

### Предположения
- Система уже имеет базовую функциональность и работает в production
- Существует стабильная база пользователей
- Есть потребность в масштабировании для поддержки большего количества пользователей
- Бюджет позволяет инвестировать в инфраструктуру

## 1. Постановка задачи
Разработка веб-приложения для онлайн-обучения и тестирования знаний.

## 2. Функциональные требования

### 2.1 Управление курсами
- Создание и редактирование курсов
- Прохождение курсов
- Генерация PDF-сертификатов после успешного прохождения

### 2.2 Система тестирования
- Валидация ответов пользователей
- Ограничение количества попыток после неправильных ответов
- Отслеживание прогресса прохождения

### 2.3 Система достижений
- Создание достижений авторами курсов
- Получение достижений пользователями
- Просмотр списка достижений

### 2.4 Управление пользователями
- Система ролей (автор, пользователь, администратор)
- Административная панель
- Управление заявками на получение прав автора

### 2.5 Система заявок на авторство
- Создание заявок пользователями
- Рассмотрение заявок администраторами
- Принятие/отклонение заявок

## 3. Нефункциональные требования

### 3.1 Масштаб системы
- Целевое количество активных пользователей в день (DAU): 1,000,000

### 3.2 Производительность
- Время отклика при получении списка курсов: 2-5 секунд
- Время отклика при получении информации о конкретном курсе: 1-2 секунды

### 3.3 Безопасность
- Аутентификация на основе JWT токенов
- Rate limiting для защиты от DoS-DDoS атак
- Защита от SQL-инъекций
- Безопасное хранение паролей
- Защита от XSS атак

## 4. Архитектура системы

### 4.1 Компоненты системы
- Клиентское приложение (Web)
- Load Balancer
- Микросервисы:
  - Сервис PDF (генерация сертификатов)
  - Сервис достижений
  - Сервис курсов
  - Сервис прогресса

### 4.2 База данных
- PostgreSQL как основная БД
- Репликация БД для повышения отказоустойчивости
- Кеширование для оптимизации производительности

### 4.3 Особенности реализации
- PDF сертификаты генерируются на лету, без постоянного хранения
- Каскадное удаление данных (например, удаление автора влечет удаление его курсов)
- Rate limiting для защиты от перегрузки

## 5. Масштабируемость

### 5.1 Стратегия масштабирования
- Фокус на горизонтальном масштабировании
- Избегание Single Point of Failure (SPOF)
- Возможность использования как собственных, так и арендованных серверов

### 5.2 Кеширование
- Использование Redis для кеширования
- Кеширование часто запрашиваемых данных
- Оптимизация производительности через кеширование

## 6. Безопасность

### 6.1 Защита данных

### 6.3 Работа с файлами

### 6.4 Аудит действий

## 8. Расчеты

### 8.1 Расчет RPS (Requests Per Second)
- DAU: 1,000,000 пользователей
- Предположим, что пользователь активен 2 часа в день
- Пиковая нагрузка: 3x от средней
- Расчет:
  - Среднее количество запросов в день: 1,000,000 * 2 часа * 60 минут * 60 секунд = 7,200,000,000 запросов
  - Средний RPS: 7,200,000,000 / (24 * 60 * 60) ≈ 83,333 запросов/сек
  - Пиковый RPS: 83,333 * 3 ≈ 250,000 запросов/сек

### 8.2 Расчет трафика
- Средний размер ответа API: 2KB
- Расчет трафика в секунду:
  - 250,000 RPS * 2KB = 500MB/сек
  - В день: 500MB * 60 * 60 * 24 ≈ 43.2TB/день

### 8.3 Расчет хранилища
- Размер записи в БД:
  - Пользователь: 1KB
  - Курс: 5KB
  - Раздел: 10KB
  - Прогресс: 2KB
  - Достижение: 1KB
- Предположим:
  - 1,000,000 пользователей
  - 10,000 курсов
  - 100,000 разделов
  - 5,000,000 записей прогресса
  - 1,000,000 достижений
- Общий размер данных:
  - (1M * 1KB) + (10K * 5KB) + (100K * 10KB) + (5M * 2KB) + (1M * 1KB) ≈ 22GB
- С учетом индексов и репликации (3x): 22GB * 3 ≈ 66GB
- Годовой рост (предположим 50%): 66GB * 1.5 ≈ 100GB/год

### 8.4 Расчет кеширования
- Предположим, что 80% запросов можно кешировать
- Размер кеша: 66GB * 0.8 ≈ 53GB
- Рекомендуемый размер Redis: 100GB (с запасом)
